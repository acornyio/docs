# Design: Chinese (zh) Multilingual Support for Acorny Docs

- **Date:** 2026-06-26
- **Branch / worktree:** `feat/i18n-zh` → `.worktrees/feat-i18n-zh`
- **Status:** Approved (brainstorming phase)

## Goal

Add Simplified Chinese (`zh-CN`) as a second language for the Acorny Help Center
(docs.acorny.io), with a language switcher in the header (desktop) and mobile menu.
All 26 existing English content pages get full Chinese translations, and the Chinese
site receives SEO parity (structured data, breadcrumbs, hreflang) with the English site.

## Decisions (locked during brainstorming)

1. **Scope:** Translate all 26 English content pages + add a Chinese homepage.
2. **URL strategy:** English stays at the site root (existing URLs unchanged, no
   redirects, zero impact on already-indexed pages). Chinese lives under `/zh/`.
3. **Screenshots:** Reuse the existing (English) screenshots on Chinese pages.
4. **Approach:** Full Starlight-native i18n **plus** extending the custom
   `inject-structured-data.mjs` script so Chinese pages keep structured-data/SEO parity.

## Architecture & Routing

- Starlight native i18n via `locales` config. Use a **root locale** for English so its
  files do not move and its URLs keep no `/en/` prefix:
  - `defaultLocale: 'root'`
  - `root: { label: 'English', lang: 'en' }` → content at `src/content/docs/<section>/…`
  - `zh: { label: '简体中文', lang: 'zh-CN' }` → content at `src/content/docs/zh/<section>/…`
- Starlight automatically emits HTML `<link rel="alternate" hreflang="en|zh-CN|x-default">`
  on every page and indexes Pagefind search per locale.
- Starlight ships built-in `zh-CN` UI strings (search placeholder, "On this page",
  pagination, etc.), so no manual UI-string localization is required.

## `astro.config.mjs` changes

- `title` becomes a per-locale object keyed by BCP-47 lang tag:
  `{ en: 'Acorny Help Center', 'zh-CN': 'Acorny 帮助中心' }`.
- Add `defaultLocale: 'root'` and the `locales` map described above.
- For **every** sidebar group and sidebar item, add
  `translations: { 'zh-CN': '…' }` (BCP-47 keys). Examples:
  - "Getting Started" → "入门"
  - "Import & Sync" → "导入与同步"
  - "Review & Recall" → "复习与回顾"
  - "Extensions & Apps" → "扩展与应用"
  - "Account & Data" → "账户与数据"
  - "Troubleshooting" → "故障排查"
  - Plus per-page labels (e.g. "What is Acorny?" → "Acorny 是什么？").
- Configure `@astrojs/sitemap` with an `i18n` option (see "Sitemap hreflang" risk note).
- The global `description` stays English; Chinese page descriptions come from each
  translated page's frontmatter `description`.

## Content translation (`src/content/docs/zh/`)

- Mirror the full structure: one `zh/<section>/<page>.md` for each of the 26 English
  pages, plus a new `zh/index.md` (Chinese homepage).
- Keep structure identical: same heading hierarchy, same numbered steps, same code
  blocks, same frontmatter keys. Translate `title`, `description`, and body prose.
- **Reuse the same screenshot paths** (`/images/…`) — no new image assets.
- Consistent terminology glossary (apply across all pages):
  - Highlights → 高亮
  - Recall cards → 复习卡
  - Spaced repetition → 间隔重复
  - Import → 导入
  - Sync → 同步
  - Review → 复习
  - Browser extension → 浏览器扩展
  - Source → 来源
  - Token → 令牌
  - Highlights list → 高亮列表

## Structured-data script — make locale-aware (`scripts/inject-structured-data.mjs`)

The script already derives routes from file paths relative to `src/content/docs/`, so
`zh/getting-started/quick-start.md` already resolves to `/zh/getting-started/quick-start/`
and `url` becomes `https://docs.acorny.io/zh/…`. Required changes:

1. Add `localeFromRoute(route)` → returns `'zh-CN'` when the route starts with `/zh/`,
   otherwise `'en'`.
2. Replace the hardcoded `inLanguage: 'en'` in `buildJsonLd` with the page's locale.
3. `buildBreadcrumbSchema`: detect the `/zh/` prefix — the section key is at index `[1]`
   (not `[0]`) for Chinese pages. Add a `sectionBreadcrumbsZh` registry (translated
   section names + `/zh/`-prefixed section landing URLs) and select it based on locale.
   Chinese home (`/zh/`) gets no breadcrumb (same as English `/`).
4. The global Organization / WebSite / SearchAction graph nodes stay unchanged.

## Sitemap hreflang (verify during build)

- Configure `sitemap({ i18n: { defaultLocale: 'en', locales: { en: 'en-US', zh: 'zh-CN' } } })`.
- **Risk:** root-locale English (no `/en/` segment) may not auto-pair with Chinese via
  the sitemap `i18n` option. Starlight's own **HTML `hreflang` is primary and works
  regardless of the sitemap config.** If XML pairing fails at build time, drop the
  sitemap `i18n` option and rely on HTML hreflang. Decide based on the actual build output.

## UX — language switcher

- **No new component needed.** With `locales` configured, the existing built-in
  `LanguageSelect` (already wired into `Header.astro` for desktop and
  `MobileMenuFooter.astro` for mobile) activates automatically and renders an
  "English / 简体中文" dropdown.
- No changes to `Head.astro`, `Header.astro`, or `MobileMenuFooter.astro`.

## Tests

- `scripts/docs-site.test.mjs`:
  - Assert Chinese pages exist and contain translated titles (e.g.
    `/zh/import-sync/kindle/index.html`).
  - Assert HTML `hreflang` alternates on an English page
    (e.g. `<link rel="alternate" hreflang="zh-CN" …>` on `import-sync/kindle/index.html`).
  - Assert `inLanguage":"zh-CN"` JSON-LD and Chinese breadcrumb names on a Chinese page.
  - Add Chinese routes to the "required files" and sitemap checks.
  - All existing English assertions must remain green.
- `scripts/inject-structured-data.test.mjs`:
  - Add a unit test that passes a `/zh/…` route page into `buildJsonLd` (or the breadcrumb
    builder) and asserts `inLanguage: 'zh-CN'` plus Chinese breadcrumb section name/URL.

## Out of scope

- `404.md` stays English (Starlight uses a single 404; it is `noindex`).
- No changes to English URLs, `src/content.config.ts`, or the
  `Head` / `Header` / `MobileMenuFooter` components.
- No Chinese-specific screenshots (reuse English ones).

## Workflow

All implementation happens in the `feat/i18n-zh` worktree at `.worktrees/feat-i18n-zh`.
Run `pnpm test` (which rebuilds first) inside the worktree before finishing.
