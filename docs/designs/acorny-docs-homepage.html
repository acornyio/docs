Quick recommendation Start by saving only lines you would genuinely want to recall a week later. Acorny becomes more useful when the capture step stays selective.

The daily review loop

The most important product idea is not storage. It is retrieval. That is why this docs direction keeps bringing the user back to the same three-step loop instead of diffusing attention across too many disconnected features.

workflow 
capture(source, quote, note)
  -> createCard(type: "cloze" | "qa")
  -> reviewWhenDue()
  -> scheduleAgain(basedOnRecall)

Browser extension capture

The first-run experience should explain exactly what happens when a user highlights a line: where it is stored, what metadata comes with it, and how it becomes a review item later. That reduces the “is this just another clipper?” question immediately.

Reader imports

Acorny should position reader imports as continuity, not ingestion for its own sake. The docs can frame imports around one promise: whatever tool you used to read, your review rhythm still happens in one place.

Recall cards

The homepage introduces the product. The docs should explain when to pick each card type.

  • Cloze works best when the original sentence is already compact and you want to blank out the key concept.
  • Q&A works better when the line contains an idea that benefits from reframing into your own prompt.
  • Good cards are short, specific, and tied to a source worth revisiting.
Design note carried into docs MarkText’s docs feel trustworthy because the navigation, search, and reading column all stay disciplined. Acorny benefits from the same restraint: one accent, clean panels, and narrow prose.

Spaced repetition

Spaced repetition should be explained in product language, not textbook jargon. Users mainly need to understand that remembered cards move further out, while uncertain cards return sooner.

Privacy & exports

The current site already says reading data is private to the user account and that export matters. Those are powerful trust points. This docs direction gives them a dedicated place near the front instead of burying them deep in FAQ copy.

  • Highlights are private unless the user chooses to share them.
  • Exports matter because reading data is part of the user’s knowledge base.
  • Permission scopes should be explained in the context of capture and restore, not generic tracking language.

FAQ

Use the FAQ as a friction reducer, not as the main sales layer. Questions about pricing, future paid features, exports, and browser permissions should remain, but they should come after the user already understands the product loop.
